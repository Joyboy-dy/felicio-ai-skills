# Project structure

## Required files (any layout)

```
vite.config.ts        plugins: [tanstackStart(), viteReact()]  (React plugin after tanstackStart; hosting plugin per adapter)
src/router.tsx        export function getRouter() { return createRouter({ routeTree, ... }) }
src/routes/__root.tsx document shell: <HeadContent /> in <head>, <Scripts /> at the end of <body>
src/routeTree.gen.ts  generated by the dev server or build; never edit, commit it or ignore it per repo policy
```

Optional: `src/start.ts` (`createStart`: global middleware, `defaultSsr`, serialization adapters), `src/server.ts` (custom server entry), `src/client.tsx` (custom hydration).

`tsconfig.json`: `moduleResolution: "Bundler"`, `jsx: "react-jsx"`, `strictNullChecks`. Keep **`verbatimModuleSyntax` off**: the docs warn it can pull server code into the client bundle. Path alias `~/*` → `./src/*` with `resolve.tsconfigPaths: true` in Vite.

## Default layout for a new project

Use it only when the repository has no convention yet. It applies the official `.functions.ts` / `.server.ts` split per feature.

```
src/
  routes/                       URL tree only: thin route files
    __root.tsx
    index.tsx
    _authed.tsx                 pathless layout: beforeLoad auth gate
    _authed/
      projects.index.tsx
      projects.$projectId.tsx
    api/
      webhooks.stripe.ts        server route for an external caller
  features/
    projects/
      projects.functions.ts     createServerFn: validator, authorization, call server code
      projects.server.ts        DB queries, SDK calls, secrets (import-protected)
      projects.schemas.ts       Zod schemas + z.infer types (client-safe)
      projects.queries.ts       queryOptions factories (when TanStack Query is used)
      components/               feature UI
  components/                   shared UI primitives (or components/ui for shadcn)
  server/                       cross-cutting server-only code: db.server.ts, auth.server.ts, env.server.ts
  middleware/                   createMiddleware definitions (auth, logging)
  lib/                          client-safe cross-cutting helpers
  styles/app.css
  router.tsx
  start.ts
  routeTree.gen.ts
```

Rules that make this layout work:

- A feature folder owns its server functions, server code, schemas and UI. Another feature imports its `*.functions.ts`, `*.schemas.ts` or `*.queries.ts`, never its `*.server.ts` from client code.
- Default import protection denies `**/*.server.*` files to the client, not folders. Either name every server file `*.server.ts`, add `import '@tanstack/react-start/server-only'` at the top, or extend the rule: `tanstackStart({ importProtection: { client: { files: ['**/*.server.*', '**/server/**'] } } })`.
- Small app: `src/utils/<name>.functions.ts` + `<name>.server.ts` (the docs' own example) is fine. Introduce `features/` when several domains appear.
- Colocation alternative: files or folders prefixed with `-` inside `src/routes` (`-components/`, `-queries.ts`) are ignored by the route generator. Use it for code used by a single route; keep cross-route code in `features/`.

## File-based routing cheat sheet

| Pattern                           | Meaning                                                      |
| --------------------------------- | ------------------------------------------------------------ |
| `__root.tsx`                      | Root route, must sit at the root of `src/routes`             |
| `index.tsx`                       | Exact match of the parent path                               |
| `posts.tsx` + `posts.$postId.tsx` | `.` nests: `/posts` layout with `/posts/:postId` child       |
| `posts/route.tsx`                 | Route file for a directory (same as `posts.tsx`)             |
| `$postId`                         | Dynamic segment, read with `Route.useParams()`               |
| `{-$lang}`                        | Optional segment                                             |
| `files.$.tsx`                     | Splat, value in `params._splat`                              |
| `_authed.tsx`, `_authed/…`        | Pathless layout: wraps children without adding a URL segment |
| `posts_.$postId.edit.tsx`         | Trailing `_` opts out of the parent layout                   |
| `(marketing)/`                    | Group folder: organizes files, no URL segment                |
| `-components/`, `-utils.ts`       | Ignored by the route generator, safe for colocation          |
| `sitemap[.]xml.ts`                | `[]` escapes a character: `/sitemap.xml`                     |

Flat and directory styles can be mixed; follow what the repo already does. Start always code-splits routes automatically (the loader stays in the main chunk); `.lazy.tsx` files are not needed.

## Placement decisions

| Need                                                | Place it in                                                    |
| --------------------------------------------------- | -------------------------------------------------------------- |
| Data for a page, needs secrets or the DB            | server function in `*.functions.ts`, called by the loader      |
| Data from a public API, no secret                   | loader directly, or a `queryOptions` factory                   |
| Mutation from the UI                                | POST server function + `useServerFn`                           |
| Webhook, OAuth callback, public REST endpoint, file | server route under `src/routes/api/`                           |
| Cross-cutting check for many server functions       | function middleware (`createMiddleware({ type: 'function' })`) |
| Check or header for every request                   | request middleware, registered in `src/start.ts`               |
| Same code, different server/client implementation   | `createIsomorphicFn().server(...).client(...)`                 |
| Browser-only widget (maps, editors, `window`)       | `<ClientOnly fallback>` or route `ssr: false`                  |
| Search-param shape and defaults                     | `validateSearch` on the route that owns the params             |
